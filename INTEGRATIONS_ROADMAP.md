## Roadmap proposée
1. **Externaliser et rendre dynamiques les filtres avancés (Python/ML)** : les filtres actuels (`FilterController`, `CandleStructureFilter`, `BenfordLawFilter`) exécutent des calculs lourds côté JVM; prévoir un service Python dédié pour les signaux statistiques tout en conservant `StrategyConfig` pour activer/désactiver dynamiquement les filtres.【F:src/main/java/finance/project/api/controllers/FilterController.java†L28-L199】【F:src/main/java/finance/project/api/filters/rules/CandleStructureFilter.java†L20-L194】【F:src/main/java/finance/project/api/filters/rules/BenfordLawFilter.java†L28-L145】【F:src/main/java/finance/project/api/config/StrategyConfig.java†L29-L61】
2. **Optimiser l’export OHLCV** : factoriser les flux d’écriture (Batch JDBC ou COPY) pour les imports massifs TradingView/CME actuellement gérés par `CandleServiceJPA` via `saveCandlesToDatabase` afin de réduire la pression sur JPA et le flush manuel.【F:src/main/java/finance/project/api/services/CandleServiceJPA.java†L321-L399】
3. **Enrichir les endpoints de stats de lecture** : ajouter des routes de synthèse (ex. winrate global, drawdown) en se basant sur `PerformanceService` et `TradeCompletedService`, aujourd’hui exposés uniquement via `/all-strategies` et `/get-trades-strategy`.【F:src/main/java/finance/project/api/controllers/BacktestController.java†L156-L173】【F:src/main/java/finance/project/api/services/PerformanceService.java†L19-L74】【F:src/main/java/finance/project/api/services/TradeCompletedService.java†L20-L47】
4. **Sécuriser les secrets & profils** : déplacer les clés API et identifiants MySQL hors `application.properties` (profil `dev`/`prod`, vault ou variables d’environnement).【F:src/main/resources/application.properties†L20-L53】
